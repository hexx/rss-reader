# 課題解決プロンプト: E2Eテストの再検討と過剰テストの整理

## 1. 役割定義 (Persona)
あなたはテスト戦略のアーキテクトです。テストピラミッドの原則に基づき、価値の低いテストの削除・置き換え、およびテスト実行の最適化を行ってください。

## 2. 背景・前提条件 (Context)

### E2Eテストの現状
- **ファイル**: `/workspace/e2e/app.spec.ts`
- **内容**: Playwright を使った3つのテストケース
  1. デスクトップレイアウトでサイドバーが表示されること
  2. モバイルレイアウトでメニューボタンが表示されること
  3. 「既読にする」ボタンで記事が消えること
- **根本的問題**: 全APIレスポンスを `page.route()` でモック（`mockApi` 関数）しており、実際のバックエンドと一切通信していない。これは「End-to-End」テストではなく「モックを使ったブラウザ表示確認」に過ぎない。
- **起動方法**: `npm run dev:client`（Vite dev server）のみ起動し、ワーカーバックエンドは起動しない。
- **CI負荷**: `.github/workflows/ci.yml` の `test-e2e` ジョブで毎回 `npx playwright install --with-deps`（ブラウザインストール）を実行しており、実行時間が長い。

### 過剰なユニットテスト
- **`/workspace/src/db/index.test.ts`**: `getDb` が `drizzle()` を呼んで戻り値を返すことだけを確認する1ケース。モックの動作確認に過ぎず、`worker.test.ts` や `sync.test.ts` の実DBテストで既にカバーされている。
- **`/workspace/src/utils/sleep.test.ts`**: `setTimeout` ラッパーのテスト。vitest のフェイクタイマー自体の動作確認になっており、プロダクトコードの品質保証にはほぼ寄与しない。
- **CIジョブ `test-e2e`**: 上記の表面的なE2Eテストのためにブラウザインストールを含むジョブが毎回実行されている。

### 関連ファイル
- `/workspace/e2e/app.spec.ts`
- `/workspace/playwright.config.ts`
- `/workspace/src/db/index.test.ts`
- `/workspace/src/utils/sleep.test.ts`
- `/workspace/.github/workflows/ci.yml`
- `/workspace/package.json`（scripts: test:e2e）

## 3. 解決すべきゴール (Goal & Objective)

### E2Eテスト
- [ ] E2Eテストの価値と保守コストを評価し、以下のいずれかの方針を選択・実行する：
  - **方針A（推奨）**: 完全に削除し、React Testing Library のコンポーネントテストで置き換える。
    - `e2e/` ディレクトリを削除
    - `playwright.config.ts` を削除
    - `package.json` から `test:e2e` スクリプトと `@playwright/test` 依存を削除
    - `.github/workflows/ci.yml` から `test-e2e` ジョブを削除
  - **方針B**: 本格的なE2Eテストに作り直す。
    - wrangler で実際のバックエンドを起動
    - APIモックを廃止し実DB（sql.js in-memory）に対してテスト
    - 適切なE2Eシナリオ（購読追加→同期→記事表示→既読化）を実装
- [ ] 方針Aを採用する場合、削除したE2Eテストが検証していた内容が、別途 React Testing Library のテストでカバーされていることを確認する（issue-202607011124-1.md 参照）。

### 過剰テストの整理
- [ ] `db/index.test.ts` を削除するか、実DBを使った意味のあるテストに置き換える
- [ ] `sleep.test.ts` を削除する（保持しても害は小さいため任意）
- [ ] CIジョブから `test-e2e` を削除（方針Aの場合）

## 4. 期待する成果物 (Output Format)
- 選択した方針とその理由の簡潔な解説
- 削除・修正したファイルの一覧
- CIパイプラインの更新（該当する場合）
- `npm run test` が全件パスすることの確認

## 5. 実行開始の合図
このプロンプトを理解したら、「タスクを開始します」と宣言し、まず現在の `e2e/app.spec.ts` の詳細な評価から始めてください。
