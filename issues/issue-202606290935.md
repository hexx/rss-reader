# 課題解決プロンプト: Cloudflare認証切れ時のメール通知重複問題

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび問題解決のエキスパートです。以下のコンテキストとゴールを基に、正確かつ効率的な修正/実装を行ってください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**: Cloudflare Zero Trust（旧 Cloudflare Access）で認証が切れた後、利用者がメールアドレスを入力して認証コードを要求すると、認証コードを含むメールが2通送信される。本来は1通でよい。
- **再現手順**:
  1. Cloudflare Zero Trust で保護されたアプリケーションにアクセスする
  2. 認証セッションが切れる（またはシークレットウィンドウで開く）
  3. メールアドレスを入力して OTP 認証コードを要求する
  4. メールが2通届く（認証コードは同一だがメールが重複している）
- **原因の考察**: コードの問題ではなく、Cloudflare Zero Trust ダッシュボードの設定に起因する。以下の可能性が考えられる：
  - Cloudflare Zero Trust 上で同一ユーザーに対して複数の通知設定が重複登録されている
  - 複数の Access Policy が同じアプリケーションに適用されており、それぞれがメール通知を送信している
  - Identity Provider の設定で通知が二重にトリガーされている
- **関連リソース**:
  - Cloudflare Zero Trust ダッシュボード: https://one.dash.cloudflare.com/
  - 設定箇所: Settings → Notifications, Access → Applications

## 3. 解決すべきゴール (Goal & Objective)
- [ ] Cloudflare Zero Trust ダッシュボードで、重複している通知設定・Access Policy を特定する
- [ ] 不要な通知設定を削除または統合し、メール送信を1通に抑える
- [ ] 修正後、認証切れ→メールアドレス入力→OTP受信 のフローをテストし、メールが1通であることを確認する

## 4. 期待する成果物 (Output Format)
- Cloudflare Zero Trust の設定変更内容（変更前後のスクリーンショットまたは設定値）
- 設定変更の理由とアプローチの簡潔な解説
- 認証フローの動作確認結果（メールが1通になったことの確認）

## 5. 判定理由（WONTFIX）
本課題はコードベース（rss-reader リポジトリ）に修正対象のコードが存在せず、Cloudflare Zero Trust ダッシュボードの設定変更で対応すべき問題です。コード修正では解決できないため、WONTFIX とします。

## 6. 推奨アクション
1. [Cloudflare Zero Trust ダッシュボード](https://one.dash.cloudflare.com/) にログインする
2. **Access → Applications** で対象アプリケーションのポリシーを確認し、重複がないか調べる
3. **Settings → Notifications** でメール通知設定に重複がないか確認する
4. 重複を解消後、認証切れ状態で OTP リクエストをテストする
