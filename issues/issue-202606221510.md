# 課題解決プロンプト: キーボードショートカット「v」キーで記事を読む、「b」キーでコメントを読む機能の追加

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび問題解決のエキスパートです。以下のコンテキストとゴールを基に、正確かつ効率的な修正/実装を行ってください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**: 現在のRSSリーダーには「m」キーで既読にするキーボードショートカットがあるが、記事を開いたりコメントページを開いたりするショートカットがない。マウスでリンクをクリックする必要があるため、キーボードだけで記事を読むワークフローが実現できない。
- **要望**:
  - 「v」キー: 画面上の最初の未読記事のURLを新しいタブで開く（「記事を読む」リンクと同じ動作）
  - 「b」キー: 画面上の最初の未読記事のはてなブックマークコメントページを新しいタブで開く（「コメントを読む」リンクと同じ動作）
- **関連ファイル/コード**:
  - `src/client/App.tsx` — メインのアプリケーションコンポーネント。既存の「m」キーショートカットの`useEffect`がある。
  - `src/client/components/ArticleCard.tsx` — 記事カードコンポーネント。`getHatenaEntryUrl`関数でコメントページURLを生成。
  - `src/client/articlePagination.ts` — 記事のページネーション管理。

## 3. 解決すべきゴール (Goal & Objective)
- [ ] 「v」キーを押すことで、画面上の最初の未読記事のURLを新しいタブで開く
- [ ] 「b」キーを押すことで、画面上の最初の未読記事のはてなブックマークコメントページを新しいタブで開く
- [ ] キーボードショートカットがテキスト入力中（検索フォームなど）には発火しないよう制御する（既存の「m」キーと同じ制御）
- [ ] 既存の「m」キーショートカットの`useEffect`を拡張する（新しい`useEffect`を追加しない）
- [ ] `getHatenaEntryUrl`関数を`ArticleCard.tsx`から`App.tsx`にインポート、または共通のヘルパーファイルに移動する
- [ ] 既存のテストを壊さないこと

## 4. 期待する成果物 (Output Format)
- 修正が完了したコード一式（`src/client/App.tsx`の修正、必要に応じて`ArticleCard.tsx`の修正）
