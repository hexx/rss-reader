# 課題解決プロンプト: 熟練エンジニア視点のコードレビュー指摘事項を一括解消する

## 1. 役割定義 (Persona)
あなたは熟練したフルスタック Web エンジニア兼レビュアーです。本リポジトリ（RSS Reader：Cloudflare Workers + D1 + Hono + React 19 + Drizzle）に対して、熟練者の目線で「未熟だな／恥ずかしい」と感じる設計・実装・運用の問題点を網羅的に解消してください。PR レビューで後輩に出したくなるレベルの指摘を、実装可能な形に整理し直すことが目的です。

## 2. 背景・前提条件 (Context)
- 既存の実装は「動く」が、Cloudflare Workers・D1・Drizzle・React 19 の慣習に反する箇所が複数あり、本番運用に耐える品質ではない。
- 機能追加よりも「いまあるコードの品質改善」を優先する。
- 既存テスト（`npm run test`、`npm run test:e2e`）を壊さないこと。
- 既存の公開 API（HTTP エンドポイント、共有型、UI/UX 挙動）の後方互換は可能な限り維持する。
- 関連ファイル/指摘箇所:
  - `src/worker.ts`（エラーハンドリング、catch-all、formatDate、normalizeSiteUrl、PATCH 既読反転不可、型依存）
  - `src/workflows/sync.ts`（マジックナンバー、N+1 ループ、逐次処理、トランザクション未使用、レース）
  - `src/services/scraper.ts`（SSRF 対策の正規表現の脆さ、リダイレクト／タイムアウト設計、selector 場当たり、noscript 過剰削除、rss-parser のモジュールトップ生成）
  - `src/services/hatena.ts`（1〜3 秒スリープ、UA 二重化、ページネーション未対応、Math.random 直利用）
  - `src/services/ai.ts`（プロバイダ未メモ化、トークン基準でない cutoff、system プロンプト重複、サロゲートペア非考慮）
  - `src/utils/sanitizeHtml.ts` / `src/client/utils/sanitizeClientHtml.ts`（二重実装残骸、noscript 扱い、`<svg>`/`<use>` の扱い）
  - `src/client/App.tsx`（God コンポーネント、status 優先順位 ?? チェーン、sheetOpen 状態位置）
  - `src/client/hooks/useArticles.ts`（requestIdRef + paramsRef + reloadToken の三重管理、暗黙の refresh 契約、死コード）
  - `src/client/components/SourceManager.tsx`（`role="button"` + `tabIndex={0}` 自前、stopPropagation、誤命名、focus-ring 欠如）
  - `src/client/components/ArticleCard.tsx`（二重サニタイズ言い訳、`sourceLabel` / `formatDate` 重複、`getHatenaEntryUrl` の正規表現脆弱性）
  - `src/db/schema.ts` / `drizzle/0000_*.sql` / `drizzle/0001_*.sql`（ALTER TABLE 追記による乖離）
  - `src/test-utils/sqljs-db.ts`（CREATE TABLE 手書きの二重管理）
  - `wrangler.toml`（`compatibility_date` が古い）
  - `index.html`（`/src/client/index.css` を Vite dev path で preload）
  - `public/sw.js` / `dist-client/sw.js`（手動管理、ハッシュ不一致）
  - `tsconfig.json`（server が `src/shared` を include するが型チェックは client 側のみ）
  - `package.json`（未使用 dependency 候補、架空バージョン）
  - `src/worker.test.ts` / `sync.test.ts`（`/api/sync` の executionCtx 不在パス未テスト、フック系テスト皆無、`sanitizeClientHtml` テスト皆無、E2E が API を叩けない構成）

- [ ] `src/worker.ts` の `/api/sync` で `c.executionCtx` 不在時は 500 を返す／`void syncTask` を消し、握り潰しを撲滅する
- [ ] `src/worker.ts` の `formatDate` は不正入力時に `null` を返し、ログにユーザー入力を流さない
- [ ] `src/worker.ts` の `normalizeSiteUrl` の例外を 400 に正規化する
- [ ] `src/worker.ts` の PATCH `/api/articles/:id` で `isRead: false` を送ると未読に戻せるようにする（型・実装・テストの整合）
- [x] ~~`src/workflows/sync.ts` の `MANUAL_MAX_PER_SITE=2` / `MANUAL_MAX_TOTAL=2` を撤廃し、`ctx.waitUntil` + Cloudflare Queues（または同等の非同期キュー）ベースに置き換える。マジックナンバーには意味のある名前を付ける~~（達成済み: issue-202606290853-sync-workflow・DONE により処理上限の二重管理は解消済み。src/ に MANUAL_MAX の残存なし）

- [ ] `src/services/hatena.ts` の UA を `scraper.ts` の `browserRequestHeaders` と統一する

優先度 Medium:

- [ ] `src/utils/sanitizeHtml.ts` の `<noscript>` 扱いを再検討（ユーザー保護と過剰削除のバランス）

## 4. 期待する成果物 (Output Format)
- 修正が完了した各ファイルの差分（PR 形式の説明付き）
- 設計判断のサマリ：なぜその変更を選んだか、保留した項目は何か

- `npm run build` 通過確認
- 後続のレビュー観点として残した項目（WOULD-RATHER / WONTFIX）の一覧
