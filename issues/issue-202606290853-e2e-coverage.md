# 課題解決プロンプト: E2Eテストカバレッジの拡充

## 1. 役割定義 (Persona)
あなたは高度なQAエンジニアおよびPlaywrightテスト設計のエキスパートです。以下のコンテキストとゴールを基に、重要なユーザーフローをカバーするE2Eテストを追加してください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**:
  `e2e/app.spec.ts` にE2Eテストがわずか3ケースしかなく、以下の重要なユーザーフローが全くカバーされていない:
  - 購読の追加フロー（フォーム入力 → POST → リスト反映）
  - 購読の削除フロー（削除ボタンクリック → DELETE → リストから消える）
  - 検索機能（検索ワード入力 → フィルタリング → 結果表示）
  - ページネーション / 「さらに読み込む」
  - エラー状態の表示（APIエラー時のアラート表示）
  - ソート順の切り替え
  - 未読フィルタの切り替え
  - はてなブックマークコメントの表示
  - 記事要約セクションの表示
  - モバイルシート（ドロワー）の開閉
  - キーボードショートカット

- **再現手順**: `e2e/app.spec.ts` を読めば明らか（3テストのみ）

- **関連ファイル/コード**:
  - `e2e/app.spec.ts`
  - `playwright.config.ts`

## 3. 解決すべきゴール (Goal & Objective)
- [ ] 購読追加・削除のE2Eテストを追加する
- [ ] 検索機能のE2Eテストを追加する
- [ ] 「さらに読み込む」ボタンのE2Eテストを追加する
- [ ] APIエラー発生時のエラーメッセージ表示テストを追加する
- [ ] ソート順切り替えのテストを追加する
- [ ] キーボードショートカット（`m`キーで既読）のテストを追加する
- [ ] `mockApi` ヘルパー関数がすでに存在するので、これを活用して新しいテストを実装する
- [ ] 既存の3テストが壊れないこと

## 4. 期待する成果物 (Output Format)
- 修正が完了した `e2e/app.spec.ts` のコード（新規テストケース追加）
- 各テストケースの簡潔な説明
- `npx playwright test` の実行結果（全テストパス確認）

## 5. 実行開始の合図
このプロンプトを理解したら、「タスクを開始します」と宣言し、直ちに `e2e/app.spec.ts` の既存テスト解析から始めてください。
