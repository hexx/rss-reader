# 課題解決プロンプト: Reactコンポーネント・カスタムフックのテスト追加

## 1. 役割定義 (Persona)
あなたはフロントエンドテストのエキスパートです。React Testing Library + vitest を用いて、クライアント側のコンポーネント・カスタムフックのテストを実装してください。

## 2. 背景・前提条件 (Context)
- **現状**: RSS Reader プロジェクトにおいて、サーバー側（worker, services, workflows）のユニットテストは充実しているが、クライアント側の React コンポーネント（`App.tsx`, `ArticleCard.tsx`, `SourceManager.tsx`）とカスタムフック（`useArticles`, `useSources`, `useSubscriptions`, `useSync`, `useKeyboardShortcuts`, `useLatestRef`）にテストが一切存在しない。
- **リスク**: `App.tsx` の Optimistic Update（既読化→失敗時ロールバック）や `useArticles` の requestId によるレースコンディション防止ロジックは非常に繊細で、テストなしではリグレッションリスクが高い。
- **関連ファイル**:
  - `/workspace/src/client/App.tsx` — メインアプリケーションロジック（~300行）
  - `/workspace/src/client/components/ArticleCard.tsx` — 記事カード表示（~150行）
  - `/workspace/src/client/components/SourceManager.tsx` — 購読管理UI（~200行）
  - `/workspace/src/client/hooks/useArticles.ts` — 最も複雑なフック（ページネーション、AbortController、requestId）
  - `/workspace/src/client/hooks/useSources.ts`
  - `/workspace/src/client/hooks/useSubscriptions.ts`
  - `/workspace/src/client/hooks/useSync.ts`
  - `/workspace/src/client/hooks/useKeyboardShortcuts.ts`
  - `/workspace/src/client/hooks/useLatestRef.ts`
  - `/workspace/src/client/utils/sanitizeClientHtml.ts` — DOMParserベースのクライアント側サニタイザ（未テスト）
  - `/workspace/src/client/utils/hatena.ts` — getHatenaEntryUrl（未テスト）
  - `/workspace/src/client/utils/status.ts` — normalizeError, statusOf（未テスト）

## 3. 解決すべきゴール (Goal & Objective)
- [ ] `useArticles` フックのテストを追加する。以下を最低限カバーすること：
  - 初回ロード（offset=0）で記事が置換されること
  - loadMore で既存記事に追加されること
  - AbortController によるキャンセルでステータスが更新されないこと
  - requestId によるレースコンディション防止（古いリクエストの結果が無視されること）
  - エラー時のステータス更新
- [ ] `App.tsx` のロジックをテストする。以下を最低限カバーすること：
  - Optimistic Update: 既読化ボタン押下 → 即座にUI更新 → API失敗時にロールバック
  - Status 表示の優先順位（readStateStatus > subscriptions.status > sync.status > articlesStatus > sources.status）
  - 検索フィルタリング（matchesSearch）の各フィールド（title, summary, hatenaSummary, content, url, siteUrl, bookmarks）
  - ソート順切替時の refresh 呼び出し
- [ ] `ArticleCard.tsx` のテストを追加する：
  - formatDate の正常系/異常系（無効な日付文字列で「日時不明」）
  - sourceLabel のホスト名抽出
  - ブックマークの空コメントフィルタリング（visibleBookmarks と hasVisibleBookmarks の分岐）
  - dangerouslySetInnerHTML に sanitizeClientHtml の結果が渡されること
- [ ] `SourceManager.tsx` のテストを追加する：
  - フォーム送信時のバリデーション（空URL）
  - 購読解除ボタンのクリック伝播防止（e.stopPropagation）
  - キーボード操作（Enter/Space でのソース選択）
- [ ] `sanitizeClientHtml.ts` のテストを追加する（サーバー側 sanitizeHtml.test.ts を参考に）
- [ ] `hatena.ts` (getHatenaEntryUrl) のテストを追加する（http/https の違い）
- [ ] `status.ts` のテストを追加する
- [ ] `useKeyboardShortcuts` のテストを追加する（入力フィールドでは無効、m/v/b キー）
- [ ] 既存のサーバー側テスト（vitest run）を壊さないこと
- [ ] MSW を使用して API レスポンスをモックすること（既存の test/setup.ts を活用）

## 4. 期待する成果物 (Output Format)
- 各コンポーネント/フックに対応する `*.test.ts` または `*.test.tsx` ファイル
- テスト実行結果（`npm run test` が全件パスすること）
- 追加したテストの概要とカバレッジの方針の簡潔な解説

## 5. 実行開始の合図
このプロンプトを理解したら、「タスクを開始します」と宣言し、直ちに `useArticles.ts` の解析から始めてください。
