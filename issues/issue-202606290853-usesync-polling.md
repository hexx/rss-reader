# 課題解決プロンプト: useSyncの固定タイムアウト待ちをポーリング方式に改善

## 1. 役割定義 (Persona)
あなたは高度なフロントエンドエンジニアおよび非同期処理設計のエキスパートです。以下のコンテキストとゴールを基に、ユーザー体験を向上させる改善を行ってください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**:
  `src/client/hooks/useSync.ts` で、サーバー側の同期API（`POST /api/sync`）をキックした後、**固定の4秒間 `setTimeout`** で待ってから記事一覧をリフレッシュしている。
  ```typescript
  const SYNC_REFRESH_DELAY_MS = 4_000;
  ...
  await new Promise((resolve) => window.setTimeout(resolve, SYNC_REFRESH_DELAY_MS));
  onAfterSync();
  ```
  これには以下の問題がある:
  - 同期が4秒以内に完了しなかった場合、まだ新着記事が反映されていない状態でリフレッシュが走る（空振り）
  - 同期が1秒で完了した場合でも、ユーザーは不必要に残り3秒待たされる
  - コード内のコメントにも「本来はポーリングやSSE/WebSocketで完了通知を受け取るのが望ましい」と明記されているが実装されていない

- **再現手順**:
  1. 「同期」ボタンをクリック
  2. 4秒間待たされる（同期が1秒で終わっても待つ）
  3. 大量のフィードがある場合、4秒経っても同期が完了しておらず、リフレッシュしても記事が増えていない

- **関連ファイル/コード**:
  - `src/client/hooks/useSync.ts`
  - `src/client/App.tsx`（`useSync` の呼び出し元）
  - `src/worker.ts`（`POST /api/sync` のハンドラ）

## 3. 解決すべきゴール (Goal & Objective)
- [ ] 固定タイムアウトを廃止し、**ポーリング方式**に変更する。同期APIのレスポンスを受け取った後、定期的に（例: 1秒間隔で）記事一覧を再取得し、新着記事が増えなくなったらポーリングを停止する
- [ ] 最大ポーリング回数（または最大待機時間）の上限を設け、無限ループを防止する
- [ ] ポーリング中はUIに「同期中...」などの表示を継続し、完了したら「同期完了」に切り替える
- [ ] （発展課題）将来的に SSE（Server-Sent Events）で完了通知を受け取れるよう、サーバー側の準備も検討する
- [ ] 既存のテストが壊れないこと。また `useSync` のポーリングに関する新しいテストを追加すること

## 4. 期待する成果物 (Output Format)
- 修正が完了した `src/client/hooks/useSync.ts` のコード
- `src/client/App.tsx` の必要な修正
- ポーリング動作を検証するテストコード
- 修正理由とアプローチの簡潔な解説
