# 課題解決プロンプト: サーバー側テストのエッジケース補完と統合テスト追加

## 1. 役割定義 (Persona)
あなたはバックエンドテストのエキスパートです。既存のテストスイートを分析し、不足しているエッジケースとシナリオを補完してください。

## 2. 背景・前提条件 (Context)
- **現状**: RSS Reader のサーバー側テスト（`worker.test.ts`, `sync.test.ts` など）は全体的によく書かれており、主要なパスはカバーされている。しかし、以下のエッジケースといくつかの内部関数が未テストのまま残っている。
- **テスト手法**: vitest + sql.js (in-memory SQLite) + MSW を使用。実DBに対するテストが可能。
- **関連ファイル**:
  - `/workspace/src/worker.ts` — Hono ルーター、API エンドポイント、内部関数（formatDate, parsePaginationParam, sourceDisplayTitle, sourceSuffix など）
  - `/workspace/src/worker.test.ts` — 既存のテスト
  - `/workspace/src/workflows/sync.ts` — 同期ワークフロー
  - `/workspace/src/workflows/sync.test.ts` — 既存のテスト

## 3. 解決すべきゴール (Goal & Objective)

### worker.test.ts のエッジケース補完
- [ ] **formatDate 関数の境界値テスト**:
  - 無効な日付文字列（例: `"not-a-date"`）→ 空文字が返ること
  - `null` / `undefined` → 空文字が返ること
  - 正常な Date オブジェクト → ISO文字列が返ること
  - 正常な ISO 文字列 → ISO文字列が返ること
- [ ] **parsePaginationParam 関数のテスト**:
  - 負の数 → フォールバック値が使われること
  - `0` (limit の minimum=1 の場合) → フォールバック値が使われること
  - `"abc"` (非数値) → フォールバック値が使われること
  - `undefined` → フォールバック値が使われること
  - 有効な数値文字列 → その値が使われること
  - `Infinity` / `NaN` 文字列 → フォールバック値が使われること
- [ ] **sourceDisplayTitle 関数のテスト**:
  - 同名タイトルが2つの場合の disambiguation
  - 同名タイトルが3つ以上の場合
  - はてなソース（`b.hatena.ne.jp`）のケース
  - suffix が空文字（パスが `/` のみ）のケース
- [ ] **sourceSuffix 関数のテスト**:
  - パスが `/` だけのケース → 空文字
  - ファイル拡張子除去（`/feed.xml` → `FEED`）
  - クエリパラメータ付きURL
- [ ] **isHatenaSource 関数のテスト**:
  - `https://b.hatena.ne.jp/xxx` → true
  - `https://b.hatena.ne.jp` → true
  - 他ドメイン → false
  - 無効なURL → false（例外ではなく）
- [ ] **DELETE /api/subscriptions のテスト補完**:
  - 存在しない購読の削除 → 404 が返ること（コード上は実装済みだがテストがない）
- [ ] **sort パラメータのテスト**:
  - `sort=asc` → 昇順
  - `sort=desc` → 降順
  - `sort=invalid` → `asc` にフォールバック
  - `sort` 未指定 → `asc` にフォールバック
- [ ] **/api/articles/:id/read ルートのテスト**:
  - `/api/articles/:id` と `/api/articles/:id/read` の両方のパスが同じハンドラに到達することを確認（現在は前者のみテスト）

### 統合テストの追加
- [ ] **同期→記事取得の一連フロー**: 以下のシナリオを1つのテストで通しで検証する：
  1. 購読を追加（`POST /api/subscriptions`）
  2. 同期を実行（`POST /api/sync`）→ 記事がDBに保存される
  3. 記事一覧を取得（`GET /api/articles`）→ 保存された記事が返却される
  4. 記事を既読化（`PATCH /api/articles/:id`）→ 未読のみモードで記事が消える
- [ ] **AI要約失敗時のグレースフルデグラデーション**:
  - `generateArticleSummary` が失敗した場合、記事自体は保存されること
  - `generateHatenaSummary` が失敗した場合、hatenaSummary は null のまま記事が保存されること

### 制約事項
- [ ] 既存のテスト（`npm run test`）を壊さないこと
- [ ] テスト用のヘルパー関数（`createTestDatabase` など）を必要に応じて拡張すること
- [ ] formatDate, parsePaginationParam などは worker.ts から export されていない内部関数であるため、テストのために export を追加するか、間接的に API 経由でテストすること

## 4. 期待する成果物 (Output Format)
- 追加・修正したテストコード
- テスト実行結果（`npm run test` が全件パスすること）
- 補完したエッジケースの一覧と、それぞれのテスト方針の簡潔な解説

## 5. 実行開始の合図
このプロンプトを理解したら、「タスクを開始します」と宣言し、まず `worker.ts` の内部関数（formatDate, parsePaginationParam など）のシグネチャ確認から始めてください。
