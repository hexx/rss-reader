# 課題解決プロンプト: はてなブックマークの表示並び順を createdAt 順にし、空コメントを非表示にする

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび問題解決のエキスパートです。以下のコンテキストとゴールを基に、正確かつ効率的な修正/実装を行ってください。

## 2. 背景・前提条件 (Context)

### 問題 1: ブックマークの表示並び順が投稿順になっていない
- **現状発生している問題**: `ArticleCard.tsx` で表示されるブックマークコメントの並び順が、DB の物理的な格納順（≒ 保存順や D1 の実装依存）になっており、ユーザーがブックマークした実時刻順ではない。
- **原因**: `src/worker.ts` の `fetchBookmarksByArticleIds` が `ORDER BY` なしで `hatenaBookmarks` を SELECT している。
- **最新状況**: PR #209 の修正により、`hatenaBookmarks.createdAt` には jsonlite の `timestamp`（ユーザーがブックマークした実時刻）が入るようになった。そのため、今なら正しい順序でソートできる。
- **再現手順**: はてなブックマークを持つ記事を開き、コメント一覧の表示順と `b.hatena.ne.jp/entry/...` 上での表示順を比較する。
- **関連ファイル/コード**:
  - `src/worker.ts`（`fetchBookmarksByArticleIds`、ORDER BY が欠落）
  - `src/client/components/ArticleCard.tsx`（そのまま map でレンダリング、ソート処理なし）

### 問題 2: コメントが空のブックマークを表示しないようにしたい
- **現状発生している問題**: タグのみブックマーク（PR #209 で保存されるようになった、コメントが空文字の行）が UI に`user: ""` のように表示される。はてなブックマークの UI として「コメント無し」のブックマークは表示しないのが自然である。
- **原因**: PR #209 の修正で「タグのみブックマークでも user を保持する」ようにしたが、表示側のフィルタを追加していなかった。`ArticleCard.tsx` ですべてのブックマークを無条件にレンダリングしている。
- **補足**: ブックマーク総数のカウント（`article.bookmarks.length`）としては空コメントも含めるのが正しいが、表示の一覧としては空コメント行をスキップしたい。
- **再現手順**: タグのみブックマークが付いた記事を開き、ユーザー名だけの空行が表示されることを確認する。
- **関連ファイル/コード**:
  - `src/client/components/ArticleCard.tsx`（bookmarks.map のレンダリング箇所）
  - `src/client/types.ts`（Article 型の bookmarks: Bookmark[]）

## 3. 解決すべきゴール (Goal & Objective)

### Goal 1: ブックマークの表示並び順を createdAt 順にする
- [ ] `src/worker.ts` の `fetchBookmarksByArticleIds` で `ORDER BY hatenaBookmarks.createdAt DESC`（新しい順、はてな本家 UI と一致） または `ASC`（古い順）を追加する
- [ ] ソート方向を決める（`hatena.test.ts` や `worker.test.ts` の期待値に影響する場合は更新）
- [ ] `drizzle-orm` の `asc` / `desc` は既に `worker.ts` のトップで `import { and, asc, desc, ... }` 済みのため追加 import 不要

### Goal 2: 空コメントのブックマークを表示しない
- [ ] `ArticleCard.tsx` の `bookmarks.map` で `bookmark.comment.trim().length > 0` のものだけフィルタする
- [ ] ブックマーク総数バッジ（`article.bookmarks.length`）は全件カウントのままとし、表示行だけ絞ることを明記する

### 制約事項
- [ ] 既存のテスト（`npm run test` / `npm run test:e2e`）を壊さないこと
- [ ] 公開 API（`/api/articles` のレスポンス形式）は変更しないこと（クライアント側のみの変更）
