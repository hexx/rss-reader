# 課題解決プロンプト: デスクトップ左ペインのスクロールがページ全体に連鎖して画面が真っ白になる問題

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび問題解決のエキスパートです。以下のコンテキストとゴールを基に、正確かつ効率的な修正/実装を行ってください。

## 2. 背景・前提条件 (Context)

### 現状発生している問題
ユーザー報告: 「デスクトップの左サイドバー（購読設定ペイン）でスクロールすると、画面全体がスクロールしてしまい、画面が真っ白になる」。

前セッションで Playwright（headless Chromium, viewport 1440x900）により**再現と計測に成功**した。3重のスクロール容器が連鎖している:

| 計測項目 | 実測値 | 期待値 | 意味 |
| --- | --- | --- | --- |
| `document.documentElement.scrollHeight` | **1271** | 900 (= innerHeight) | ページ全体が371pxスクロール可能 → 端まで行くと body 背景が露出して**真っ白** |
| `aside.scrollHeight` / `clientHeight` | **1910 / 835** | 835 / 835 | 左ペイン自体が1075pxスクロール可能 → ヘッダ・入力フォーム・フッターごとペイン全体が動く（**「無意味なスクロール」の正体**） |
| ScrollArea viewport `scrollHeight` / `clientHeight` | 1820 / 652 | 1820 / 652 | 購読リスト内部のスクロール。これは**正常** |

左ペイン上でホイールした後の実測: `vpScrollTop: 1168` → `asideScrollTop: 1075` → `docScrollTop: 371` と、リスト → aside → document の順にスクロールチェーンが伝播することを確認済み。

### 根本原因（前セッションの調査結論）

**原因A（document がスクロール可能になる = 真っ白）**:
`ArticleCard` の既読ボタンの `<span className="sr-only">既読にする</span>` が `position: absolute`（Tailwind の sr-only）だが、その包含ブロック (containing block) が `main`（`overflow-y-auto` のクリッパ）の外側にあるため、`main` のクリッピングをすり抜けて document の scrollable overflow を拡張している。

実証済み（アプリ起動中に page.evaluate で検証）:
- `document.querySelectorAll('.sr-only').forEach(e => e.style.position = 'static')` → docScrollH が **1271 → 900** に正常化
- `main.style.position = 'relative'` → docScrollH が **1271 → 900** に正常化

補足: `CardHeader` には `@container/card-header`（`container-type: inline-size`）が適用されており、本来 layout containment が絶対位置指定子の包含ブロックになるはずだが、実測ではリークが発生している（包含ブロックとしては機能しても、root の scrollable overflow 計算には影響しない可能性あり）。この spec レベルの機序の完全な解明は必須ではない。**いずれの修正でも数値が正常化することは実証済み**。

**原因B（aside 自体がスクロールする = 無意味なスクロール）**:
1. `App.tsx` の `<aside>` に冗長な `overflow-y-auto` がある。本来は内部の `SourceManager`（`h-full` + base-ui `ScrollArea`）だけがリストをスクロールすべき。
2. `SourceManager` 内の購読解除ボタンの `sr-only` span も `position: absolute` で、その包含ブロックが ScrollArea root（base-ui が付与する `position: relative`）= viewport（クリッパ）の**外側**にあるため、viewport のクリッピングをすり抜けて aside の scrollable overflow を ~1910px まで拡張している（原因A と同じ機序）。
3. どのスクロール容器にも `overscroll-behavior: contain` が無いため、リストが端に達するとチェーンが上位へ伝播する。

### 再現手順

1. 開発サーバ起動: `cd /workspace && npx vite --port 5199`
2. 以下の Playwright スクリプトを実行（`node repro.mjs`）。API は `page.route` でモックする。
   - **注意**: グロブパターン `'**/api/sources'` はこの環境ではマッチしなかった。必ず URL predicate 関数を使うこと。

```js
// repro.mjs — /workspace 直下なら require('playwright') で動く（playwright はグローバルインストール済み）
import { createRequire } from 'node:module';
const require = createRequire('/usr/local/lib/node_modules/');
const { chromium } = require('playwright');

const browser = await chromium.launch({ headless: true });
const page = await browser.newPage({ viewport: { width: 1440, height: 900 } });

const sources = Array.from({ length: 30 }, (_, i) => ({
  id: `s${i}`, siteUrl: `https://blog${i}.example.com/`, title: `Blog ${i}`,
  displayTitle: `テストブログ ${i} 番目の購読フィード`, articleCount: 10 + i, unreadCount: i % 3,
}));
const articles = Array.from({ length: 5 }, (_, i) => ({
  id: `a${i}`, title: `Article ${i}`, url: `https://example.com/a${i}`,
  siteUrl: 'https://blog0.example.com/', content: '<p>c</p>', summary: 'summary',
  hatenaSummary: '', bookmarks: [], isRead: false,
  publishedAt: new Date().toISOString(), createdAt: new Date().toISOString(),
}));

await page.route((url) => url.pathname.startsWith('/api/'), (route) => {
  const { pathname } = new URL(route.request().url());
  if (pathname === '/api/sources') return route.fulfill({ contentType: 'application/json', body: JSON.stringify({ sources }) });
  if (pathname === '/api/articles') return route.fulfill({ contentType: 'application/json', body: JSON.stringify({ articles, hasMore: false }) });
  return route.fulfill({ contentType: 'application/json', body: '{}' });
});

await page.goto('http://localhost:5199/', { waitUntil: 'networkidle' });
await page.waitForTimeout(800);

const snap = () => page.evaluate(() => {
  const aside = document.querySelector('aside');
  const vp = document.querySelector('[data-slot="scroll-area-viewport"]');
  return {
    docScrollH: document.documentElement.scrollHeight,
    docScrollTop: document.documentElement.scrollTop,
    asideScrollH: aside?.scrollHeight, asideClientH: aside?.clientHeight, asideScrollTop: aside?.scrollTop,
    vpScrollH: vp?.scrollHeight, vpClientH: vp?.clientHeight, vpScrollTop: vp?.scrollTop,
  };
});

console.log('initial:', JSON.stringify(await snap()));

const box = await page.locator('[data-slot="scroll-area-viewport"]').boundingBox();
await page.mouse.move(box.x + box.width / 2, box.y + box.height / 2);
for (let i = 0; i < 30; i++) { await page.mouse.wheel(0, 300); await page.waitForTimeout(40); }
await page.waitForTimeout(500);
console.log('after wheel:', JSON.stringify(await snap()));
await browser.close();
```

**判定**: 修正前は `initial` で `docScrollH: 1271`, `asideScrollH: 1910`、`after wheel` で `docScrollTop: 371` となる。修正後は `docScrollH: 900`, `asideScrollH: 835 (= clientHeight)`、`docScrollTop: 0` が維持され、`vpScrollTop` のみが増えること。

## 3. 解決すべきゴール (Goal & Objective)
- [ ] **G1**: `document.documentElement.scrollHeight === window.innerHeight` になる（ページ全体がスクロール不能）。推奨: `main` に `relative` を付与し、sr-only の絶対位置指定子を main のクリップ内に取り込む（実証済みの手法。`sr-only` のスタイル自体は変えないこと）。
- [ ] **G2**: `aside` がスクロール不能になる（`scrollHeight === clientHeight`）。推奨: `aside` から `overflow-y-auto` を削除（内部 ScrollArea がスクロールを担当）。削除後、sr-only span の overflow は row コンテナ（`overflow-hidden`）でクリップされることを再現スクリプトで確認すること。
- [ ] **G3**: スクロールチェーンの遮断: 左ペインのリスト・`main` の記事リストが端に達しても上位へ伝播しない。推奨: ScrollArea viewport（`scroll-area.tsx` または index.css の `[data-slot="scroll-area-viewport"]`）と `main` に `overscroll-behavior: contain`（Tailwind: `overscroll-contain`）を適用。modern-web-guidance skill もこのパターンを推奨（`npx -y modern-web-guidance@latest retrieve css-layout` 参照）。
- [ ] **G4**: モバイルの Sheet（左から出るメニュー）でも同様にリストのみがスクロールし、ページが動かないこと（同じ ScrollArea を使うので G3 でカバーされる見込み。 viewport 375x667 程度でも再現スクリプトを流して確認すると尚良い）。
- [ ] 既存のテストを壊さないこと（`npm run test`、関連: `src/client/App.test.tsx`, `SourceManager.test.tsx`, `ArticleCard.test.tsx`）。スナップショットや className 断言があれば合わせて更新。
- [ ] `npm run build` が通ること。
