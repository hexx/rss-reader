# ブックマークコメントの並びは「時系列・新しい順（降順）」とし、本家デフォルトの注目順は再現しない

はてなブックマークコメントの表示順を、Bookmark Timestamp（ユーザーがブックマークした日時）の降順（新しい順）に統一する。本家エントリーページ (b.hatena.ne.jp/entry/...) のデフォルトは「注目コメント順」（LINEヤフーの建設的コメント順位付けモデルを使った非公開アルゴリズム）だが、データソースの jsonlite API はスコアを返さないため再現不能。再現可能な「新着順」を採用し、jsonlite の生レスポンス順序（新しい順）とも一致させる。方向切替UIは持たない（必要になったら後から足す）。

## Considered Options

- **本家デフォルト（注目順）の再現**: jsonlite にスコア情報がなく再現不能。スクレイピングもレート制限・規約面で現実的でないため不採用。
- **時系列・古い順（昇順）**: 議論の発生順に読める利点はあるが、RSS リーダーとして「今来ている反応」が上に来る方が自然で、jsonlite 生順序（降順）とも一致しないため、既定は降順に決定。古い順は将来のオプションとしてのみ検討。
- **方向切替UIを最初から付ける**: 要求は「順不同に見える問題の解消」であり、方向の好みは未確定の将来要件なため YAGNI で不採用。

## Consequences

- 同一「分」のブックマークは timestamp が同値になる（分精度）。`ORDER BY createdAt DESC, rowid ASC` で決定的に tiebreak する（jsonlite は新しい順で返り、その順に INSERT されるため、同一分内では rowid 昇＝先に挿入されたものが先頭＝全体の新着順と整合）。
- 既存行には旧パースバグ（epoch 秒前提→実際は `"YYYY/MM/DD HH:MM"` 文字列→`parseInt` で年だけ拾い 1970 年に潰れる）で壊れた `createdAt` が残る。upsert を `ON CONFLICT DO NOTHING` から `DO UPDATE (createdAt, comment)` に変更し、次回バックフィル同期で自然治癒させる（一次性マイグレーションはしない）。
