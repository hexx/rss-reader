# 直接取得のタイムアウト・リダイレクトループ・ボディ超過も Jina Fallback に退避する

ADR-0012 は発火条件を 403/451 に限定し、「429・タイムアウトも退避対象にする」選択肢を「相手の不調への『迂回』は律速・クールダウン（ADR-0009）の服従と矛盾する」として棄てた。しかし 2026-09-01 の実測（[issues/issue-202609010458-content-backfill.md](../../issues/issue-202609010458-content-backfill.md) 追記 5・6、Workers Logs の計装による観測）がこの前提を崩した:

- **techno-edge**: Cloudflare エグレス IP に対してのみ 5 超のリダイレクト（bot 対策ループ）を返し、`Too many redirects` で直接取得が失敗 → Jina 未発火 → **78/78 が恒久欠損**。Jina 経由では本文を正常取得できる（実測）。
- **福島大学**: 15 秒タイムアウト。サイトは複数ネットワークから接続リセットされる不安定さがあり、「タイムアウト = 一時的不調 = 次回で回復」という前提が当てはまらない（Jina からも接続リセット）。

つまり、**応答が完結した拒否・律速要求（429/503・403/451）と、応答が完結しない失敗（タイムアウト・リダイレクトループ・ボディ超過）**を同一視していたことが誤りだった。後者は「次回で回復する」とは限らず、恒久的な欠損になる。

## 決定

直接取得が失敗したときの Jina Fallback 発火条件を、403/451 に加えて**応答が完結しない失敗（タイムアウト・リダイレクトループ・ボディ超過）**に拡張する。429/503（ThrottleError、相手の明示的な律速要求）と 5xx（相手の不調）、枠待ち失敗（EgressUnavailableError）は引き続き退避しない — 律速・持ち越しの領域を維持する。

## Considered Options

- **現状維持 + Backfill で後日回復**: techno-edge 型（ループが恒久的）は同じエグレスから同じループに当たり回復しない。
- **429/503 も退避対象にする**: 相手が明示的に「遅くして」と要求しているのに迂回するのは礼儀（ADR-0009/0011）と矛盾する。退避対象から除外し続ける。
- **採用（応答が完結しない失敗のみ拡張）**: 律速要求への服従を維持したまま、恒久的に応答が完結しないサイトを救う。

## Consequences

- jina.ai 枠の使用量が増える（タイムアウトするサイトの記事ごとに Jina を叩く）。枠内間隔 3〜4 秒とクールダウン（30→60→90 分）が暴走を担保する。
- 接続リセット型のサイト（福島大学型）は Jina でも失敗する → 欠損は残り、Backfill（別課題）での後日回復に頼る。
- キーなし無料枠では 429 リスクが増えるため `JINA_API_KEY` の設定を推奨する。
- 空本文の 5 経路（拒否・タイムアウト・ループ・ボディ超過・200 抽出空）は、計装ログ（PR #377）と warn の署名で区別可能。
