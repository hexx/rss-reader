# 拒否された本文の最終退避として Jina Reader 経由の取得を導入する

ブラウザ UA への退避（ADR-0011）でも 403/451 を返す相手では本文が空のまま保存され、要約品質が黙って恒久劣化する。原因が Cloudflare 由来か共有エグレス IP 由来かは観測できないため、判定は拒否の結果（403/451）だけで行い、記事本文取得に限り **Jina Reader（`r.jina.ai`）経由の取得を最終段の退避として追加**する。Jina へのリクエストは既存の律速層に `jina.ai` 枠として統合し（キーなし無料枠 約 20 RPM 以下の専用間隔）、`JINA_API_KEY` は任意、退避の事実は ADR-0011 と同じく永続化しない。詳細は [jina-fallback.md](../specs/jina-fallback.md)。

## Considered Options

- **ブラウザ UA で足りないなら諦める**: 空本文の恒久劣化が解消されない。
- **403/451 で即 Jina（ブラウザ UA 段の廃止）**: 安価な手段（ヘッダー差替）を先に試す順序を壊し、外部依存の発火頻度を増やす。
- **退避事実を Source/記事に永続化し、次回から Jina 一直線**: 相手側の状況は変わるため、古い状態に固定するリスクの方が大きい（ADR-0011 と同じ判断）。
- **429・タイムアウトも退避対象にする**: 相手の不調への「迂回」は律速・クールダウン（ADR-0009）の服従と矛盾する。

## Consequences

- Jina の可用性・レート制限・応答形式の変更が新たな外部依存になる。jina.ai 枠の間隔はキーの有無で変えない。
- 拒否された記事 URL が第三者（Jina）に送信される。対象は購読先の公開記事 URL である。
- 退避が頻発すると同期所要時間が伸びる（記事あたり最大 +60 秒の枠待ち）。クールダウン中は待たずに本文なし保存へ流れる。
