# 未読数はクライアントで楽観減算し、サーバとは背景で突き合わせる

既読化時にサイドバーの未読数（Unread Count）が点滅する問題への対応として、未読数の更新を「サーバ応答後に再計算」から「クライアントでの楽観的減算 + PATCH 成功後のサイレント refetch による reconcile」へ変更する。旧設計（`App.tsx` の「UnreadCount の減算は sources.reload() 後に再計算されるためここでは行わない」というコメント）は単一の真値をサーバに置く簡潔さがあったが、refetch 中のスケルトン置換による全リストの点滅と、カウント反映の往復遅延という UX コストが見合わなかった。

## Considered Options

- **サーバ駆動のままスケルトン表示のみ修正**（却下）: 点滅は消えるが、カウント減少が PATCH+refetch の往復分遅れて見え、キーボードショートカット（`m` 連打）での連続既読時に違和感が残る。
- **楽観減算 + 背景 reconcile**（採用）: 即座に数字が減り、ドリフトは PATCH 成功後のサイレント refetch と react-query 既定のフォーカス時 refetch で収束する。代償として、失敗時のロールバック・二重減算ガード・0 クランプの防衛線が必須になる（詳細は `issues/issue-202607292347-unread-count-flicker.md`）。
