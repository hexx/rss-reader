# 素直なリーダ UA を既定とし、403/451 のときだけブラウザ UA に退避する

外部取得はこれまで Chrome の User-Agent を偽装していた（`browserRequestHeaders`）。RSS リーダとしての取得をbot 的に見せるより名乗る方が礼儀として筋がよく、はてな側の制限挙動との相関も切り分けておきたい。一方で本文取得が 403 になると、現行コードは**本文なしで保存し、既存記事は二度と本文を再取得しない**ため、要約品質が黙って恒久劣化する。

## 決定内容

- **全 egress の User-Agent を `rss-reader/1.0 (+https://github.com/hexx/rss-reader)` に統一**する（フィード取得・記事本文取得・はてブ jsonlite すべて。`accept-language` 等のブラウザ風ヘッダー群は残すか整理して、UA だけは正直にする）。
- **例外は 1 段だけ**: 記事本文取得が `403` / `451` を返した場合に限り、**その記事についてブラウザ UA で 1 回だけ再取得**する。退避の事実は Source にも取得枠にも保存せず、記事ごとに毎回試みる。
- **403/451 の退避は律速・クールダウンとは別扱い**（再試行ではなくヘッダーの差替であり、相手の制限要求への服従ではない）。

## Considered Options

- **一律変更・403 対策は別 Issue**: 空本文が恒久化し、要約品質が音もなく落ちる。
- **403 時は記事を保存せず次回に回す**: 復旧が「フィードが記事を載せている間」に限られる。`b.hatena.ne.jp/hotentry.rss`（実測 40 件）や `qiita.com/popular-items/feed`（30 件）のような人気フィードは回転が速く、403 が続く間は**記事そのものを恒久消失**する。429 より悪い損失に置きわるため不採用。
- **フィード取得と jsonlite だけ正直 UA、本文はブラウザ UA 維持**: 「誠実なリーダ」として自己矛盾するため不採用。

## Consequences

- bot UA を嫌う相手ではフォールバックが毎回発火する。発火頻度が高い場合のみ、退避の永続化（Source 別 UA 許可リスト）を別 Issue で検討する。
- 一時的な 5xx・タイムアウトによる空本文は依然として復旧経路がない。復旧させるなら「本文未取得を Backfill の巡回対象に含める」が自然な拡張先（ADR-0010 のカーソル・上限・律速をそのまま再利用でき、新概念は不要）。**今回では行わない**。
